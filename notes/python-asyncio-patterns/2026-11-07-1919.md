# TIL: Structured Concurrency with `asyncio.TaskGroup`

Python 3.11 introduced `asyncio.TaskGroup`, replacing the error-prone `gather()`/`create_task()` combo for managing concurrent workloads. It implements **structured concurrency**: the group acts as a context manager that guarantees all spawned tasks either complete successfully or are cancelled together if *any* single task fails. This eliminates "fire-and-forget" leaks where background tasks outlive their parent scope, silently swallowing exceptions or holding resources.

The syntax is explicit: `async with TaskGroup() as tg:` creates a scope; `tg.create_task(coro)` schedules work. On exit, `__aexit__` waits for all tasks. If one raises, the others are cancelled immediately, and the first exception is propagated (wrapped in an `ExceptionGroup` if multiple fail). This mirrors the reliability of `with open(...)` for I/O resources, but for execution lifecycles.

```python
import asyncio

async def worker(name: str, fail: bool = False):
    print(f"{name}: start")
    await asyncio.sleep(0.1)
    if fail: raise ValueError(f"{name} crashed")
    print(f"{name}: done")
    return name

async def main():
    try:
        async with asyncio.TaskGroup() as tg:
            tg.create_task(worker("A"))
            tg.create_task(worker("B", fail=True))  # Triggers cancellation of A
            tg.create_task(worker("C"))
    except* ValueError as eg:  # Python 3.11+ except* syntax
        print(f"Caught: {eg.exceptions[0]}")

asyncio.run(main())
# Output:
# A: start
# B: start
# C: start
# B: crashed
# Caught: B crashed
# (A and C cancelled silently before 'done')
```
